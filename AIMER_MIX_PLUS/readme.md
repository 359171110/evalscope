# AIMER-Mix-Plus

AIMER-Mix-Plus (AMP) is a strict data-free, training-free, cross-model channel-ranking method for routed MoE experts.
It uses the four-model AIMER-Mix weight ranking as a stable global backbone and adds pseudo-token evidence from three
independent source roles:

- `pp`: current-layer native-router pseudo responses;
- `prp`: previous-layer routed-expert write directions, normalized and filtered by the current router;
- `layerprop`: hidden-state rankings produced by a model-specific layer-propagation builder.

The fusion layer is model-agnostic. Model-specific tensor layouts and activation functions are handled by
`AIMER_Mix.model_adapter.AIMERMixModelAdapter` and the source builder.

## Policy

AMP does not require pseudo sources to agree. AIMER-Mix protects a core prefix of the target retained width. The remaining
boundary budget is selected by the weighted pseudo evidence plus the AIMER-Mix rank. A source can replace channels outside
the original AIMER-Mix top-K set.

The policy is continuous:

- source coverage and stability reduce source influence but do not disable other sources;
- disagreement is a soft penalty, not a fallback gate;
- missing sources are allowed;
- with no pseudo sources, the output is exactly the AIMER-Mix order;
- every output is a complete per-expert channel permutation;
- the ranking cache is width-specific because the rescue boundary depends on retained width.

The method never uses calibration tokens, labels, benchmark metrics, or downstream scores.

## Source roles by model

The recommended first configurations are deliberately conservative, but the code does not hardcode model names:

| Model family | Recommended initial sources | Rationale |
|---|---|---|
| Qwen3 | `pp`, optionally `prp` | Existing PP evidence is useful on Qwen3; PRP is an optional previous-write correction. |
| Qwen3.6 | `pp`, optionally `prp` | Keep PP as the main pseudo source; use PRP only as a bounded boundary source. |
| Gemma4 | `layerprop` + `prp`, optionally `pp` | LayerProp provides propagated synthetic states; PRP provides previous sparse write directions. The pseudo sources are allowed to overcome the AIMER-Mix boundary. |
| DeepSeek-V2-Lite | `pp` with low `--pp-weight`, optionally `prp` | The first dense layers are skipped by the AIMER-Mix adapter; the exporter preserves shared experts. |

These are starting points, not automatic claims about final quality. Source weights, boundary size, and source cache choice
are explicit CLI arguments.

## Build pseudo source caches

The built-in source builder creates a ranking-only cache. It supports the AIMER-Mix model adapter families:
`qwen3`, `qwen3.6`, `gemma4`, and `deepseek_v2`.

PP source:

```bash
python -m AIMER_MIX_PLUS.build_pseudo_source_artifacts \
  --model-path /path/to/model \
  --method pp \
  --output-cache /path/to/amp_sources/pp.pt \
  --router-neighbors 8 \
  --top-q 4 \
  --score-mode output
```

PRP source:

```bash
python -m AIMER_MIX_PLUS.build_pseudo_source_artifacts \
  --model-path /path/to/model \
  --method prp \
  --output-cache /path/to/amp_sources/prp.pt \
  --prp-probe-count 32 \
  --top-q 4 \
  --score-mode output
```

`--score-mode output` multiplies the pseudo nonlinear response by the aligned `down_proj` column norm. Use
`--score-mode activation` to reproduce an activation-only source.

The PRP builder uses the previous routed expert `down_proj` columns from the original checkpoint. It includes both signs
of each write direction, sends them through the current layer's native Top-K router approximation, and retains the
strongest routed bucket for each target expert. For Gemma4 the router path uses no-gamma RMS normalization, global router
scale, normalized Top-K probabilities, and per-expert scale; response scoring independently uses
`pre_feedforward_layernorm_2` and GELU-tanh. It also applies the previous post-FFN gamma product to the source write
directions. For layer 0, or a DeepSeek dense predecessor without an available write catalog, PRP falls back to the PP
source only for that layer/expert.

LayerProp is intentionally not generated by this generic source builder. A full-block LayerProp implementation must use
the target model family's native decoder forward semantics. Save its complete per-expert channel permutations in the
standard source-cache format, then pass the cache as `--source layerprop=PATH`. This keeps the AMP fusion and exporter
cross-model while allowing separate Qwen3, Qwen3.6, Gemma4, and DeepSeek layer-propagation implementations.

## Build AMP rankings

First build or reuse an AIMER-Mix cache for the exact same checkpoint. Then pass one or more source caches with
`--source SOURCE=PATH`.

Example for Gemma4 at width 512:

```bash
python -m AIMER_MIX_PLUS.build_aimer_mix_plus_artifacts \
  --model-path /path/to/gemma4 \
  --aimer-mix-cache /path/to/aimer_mix_rankings.pt \
  --source prp=/path/to/amp_sources/prp.pt \
  --source layerprop=/path/to/gemma4_layerprop/rankings.pt \
  --output-channel-cache /path/to/amp/gemma4_amp_512_rankings.pt \
  --output-profile /path/to/amp/gemma4_amp_512_profile.pt \
  --retained-channels 512 \
  --boundary-fraction 0.20 \
  --minimum-boundary-channels 32 \
  --maximum-boundary-fraction 0.35 \
  --prp-weight 1.0 \
  --layerprop-weight 1.25
```

Example for Qwen3 with PP and PRP:

```bash
python -m AIMER_MIX_PLUS.build_aimer_mix_plus_artifacts \
  --model-path /path/to/qwen3 \
  --aimer-mix-cache /path/to/aimer_mix_rankings.pt \
  --source pp=/path/to/amp_sources/pp.pt \
  --source prp=/path/to/amp_sources/prp.pt \
  --output-channel-cache /path/to/amp/qwen3_amp_576_rankings.pt \
  --output-profile /path/to/amp/qwen3_amp_576_profile.pt \
  --retained-channels 576 \
  --boundary-fraction 0.15 \
  --maximum-boundary-fraction 0.30 \
  --pp-weight 1.0 \
  --prp-weight 0.5
```

Use exactly one of `--retained-channels` and `--target-pruning-ratio`. The output profile and ranking cache must be rebuilt
for every target retained width.

Optional source controls are per source:

```text
--source-stability SOURCE=FLOAT
--source-coverage-floor SOURCE=FLOAT
--source-base-weight SOURCE=FLOAT
```

For example:

```bash
--source-stability prp=0.8 \
--source-coverage-floor layerprop=0.35 \
--source-base-weight pp=1.0
```

Source caches are checked for:

- matching model path, unless `--allow-source-model-path-mismatch` is explicitly provided;
- matching config and safetensors index SHA256 when provenance is present;
- zero calibration sequences;
- no test metrics;
- complete layer/expert/channel permutations.

## Export a checkpoint

```bash
python -m AIMER_MIX_PLUS.export_aimer_mix_plus_checkpoint \
  --model-path /path/to/model \
  --profile /path/to/amp/gemma4_amp_512_profile.pt \
  --channel-cache /path/to/amp/gemma4_amp_512_rankings.pt \
  --output-dir /path/to/checkpoints/gemma4_amp_512
```

The exporter reuses AIMER-Mix's layout handling:

- Qwen3 and DeepSeek separate gate/up/down expert tensors;
- Gemma4 and Qwen3.6 packed `gate_up_proj` tensors;
- DeepSeek routed-layer filtering and shared-expert width preservation;
- unchanged routers, dense MLPs, shared experts, multimodal tensors, and auxiliary/MTP tensors.

No compensation or down-projection folding is performed by AMP. It only changes the aligned routed channel mask.

## Cache format

A pseudo source cache contains:

```text
schema_version: 1
purpose: aimer_mix_plus_pseudo_source
model_path: checkpoint path
calibration_sequences: 0
test_metrics_used: false
block_size: channel alignment
table[layer_id].ranked_indices: [num_experts, intermediate_size]
pseudo_source.coverage: [num_layers, num_experts]
pseudo_source.stability: [num_layers, num_experts]
```

Existing ranking-only caches from PP, PRP, LayerProp, and compatible NAPS-v2 artifacts can be imported as long as they expose a
`table[layer_id].ranked_indices` permutation and satisfy the provenance/data-free checks.

## Tests

Focused tests are under `AIMER_MIX_PLUS/tests/`. They cover:

- exact AIMER-Mix equivalence with no pseudo source;
- pseudo rescue outside the AIMER-Mix top-K boundary;
- missing and conflicting source behavior;
- confidence attenuation;
- ranking-only cache loading;
- width-specific artifact metadata;
- separate and packed exporter contracts;
- Gemma4 GELU-tanh dispatch;
- previous-write direction sign orientation.

The implementation intentionally does not start experiments or model evaluation. Run the tests and builders in the target
server environment with the appropriate project dependencies.
